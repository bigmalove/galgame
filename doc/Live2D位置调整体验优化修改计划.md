# Live2D 位置调整体验优化修改计划

目标：解决以下 3 个问题并保证“所见即所得”。

1. 点击“开始调整位置”后，应关闭其他窗口并显示主界面。
2. 调整时不应被临时容器裁切，且调整结果应与实际显示大小/位置一致。
3. 调整面板在移动端可见、可操作，不会掉到屏幕外。

适用文件：
- `初始模板/脚本/galgame通用生成器/数据库界面插件.js`
- `初始模板/脚本/galgame通用生成器/数据库界面插件.css`

不处理文件：
- `初始模板/脚本/galgame通用生成器/数据库界面插件.dist.js`（构建产物，按项目约定忽略）

---

## 1. 当前问题与根因

### 1.1 “开始调整位置”未清场

当前 `showLive2DSettingsModal()` 的 `#gal-live2d-start-position-edit` 只做了：
- 保存当前 transform
- `remove()` 当前设置弹窗
- 进入 `Live2DPositionEditor.enter(characterId)`

问题：其它弹窗/面板（如角色管理、自定义弹窗、下拉层）可能仍在，导致进入调整模式后界面状态混乱。

### 1.2 调整容器不是实际舞台

当前 `Live2DPositionEditor.enter()` 会创建一个居中的临时容器：
- `#gal-live2d-position-edit-container`
- 尺寸取 `.gal-char-slot`，但位置固定在中心
- 有虚线边框并且容器本身限制可视区域

问题：
- 调整视图不是主界面的真实角色槽位（WYSIWYG 不成立）。
- 缩放/偏移计算受临时容器影响，容易“显示不全”或与最终显示不一致。

### 1.3 工具栏固定底部，移动端不可见

当前 `createToolbar()` 使用内联样式固定在：
- `position: fixed; bottom: 20px; left: 50%; transform: translateX(-50%)`
- 固定最小宽度 `min-width: 320px`

问题：
- 小屏和低高度设备下，工具栏容易被底部区域遮挡或超出可视区。
- 无移动端专用布局和安全区域（safe-area）适配。

---

## 2. 改造方案

## 2.1 进入调整模式前统一清场 + 回到主界面

新增上下文准备函数（建议名）：`prepareLive2DPositionEditContext()`

执行顺序：
1. 关闭 Live2D 预览挂载：`Live2DStage.popMount()`（若存在）。
2. 关闭所有非必要弹窗/面板（白名单保留主界面 overlay）：
- `.gal-input-modal`
- `.gal-config-modal`
- `#gal-live2d-settings-modal`
- `#gal-custom-popup`
- `.gal-z-dropdown`（仅关闭临时菜单，不关主界面核心节点）
3. 强制显示主界面：
- 若 `#gal-global-overlay` 未激活，调用现有显示逻辑。
- 确保 `.gal-game-content` 可见。
4. 等待 1-2 帧再进入编辑，避免布局未稳定导致首帧错位。

验收点：
- 点击“开始调整位置”后，界面仅保留主游戏画面 + 调整工具栏。

## 2.2 调整模式改为真实舞台（所见即所得）

核心改动：删除“居中临时裁切容器”方案，改为在主舞台直接编辑。

具体做法：
1. `Live2DPositionEditor.enter()` 不再创建 `#gal-live2d-position-edit-container`。
2. 直接挂载到 `#gal-global-overlay .gal-game-content`，优先保留当前角色真实 slot（left/right）。
3. 保留“可视参考框”，但只做引导，不参与裁切：
- 用独立 guide overlay 显示边界。
- guide `pointer-events:none`，不影响交互。
4. `exit()` 清理 guide，不再处理临时容器的创建/销毁分支。

收益：
- 调整过程与最终渲染环境一致。
- 不再出现“编辑时显示不全、保存后位置不一致”的体验差异。

## 2.3 调整面板布局重构（移动端优先）

将工具栏从“硬编码内联样式”改为“类名 + CSS 媒体查询”。

桌面布局：
- 底部居中保持不变。
- 增加 `max-width`、`max-height` 和内部滚动兜底，避免内容溢出。

移动端布局（`max-width: 48rem` 或低高度）：
- 改为顶部吸附或中上区域悬浮，不使用固定底部。
- 宽度 `min(96vw, 560px)`，高度可滚动。
- 使用安全区域：`env(safe-area-inset-top/bottom)`。
- 按钮行改为两行自适应，保证“保存/取消”始终可点击。

可选增强：
- 增加“收起/展开”按钮，默认展开核心控件，进一步避免遮挡主画面。

## 2.4 变换值一致性修正

为保证“面板数值 = 实际结果”，补充两点：
1. 编辑态读取 transform 时，统一使用当前舞台真实 `rect/baseScale` 计算（避免临时容器偏差）。
2. `scaleBase=height` 场景下，`offsetY` 与 `originY` 基准保持与正式渲染一致。

## 3. 具体改动点（函数级）

`初始模板/脚本/galgame通用生成器/数据库界面插件.js`
- `showLive2DSettingsModal(characterId)`
  - `#gal-live2d-start-position-edit` 点击流程前增加“清场 + 主界面恢复”。
- `Live2DPositionEditor.enter(characterId)`
  - 去掉临时居中容器创建逻辑，改为真实舞台编辑。
- `Live2DPositionEditor.exit(save)`
  - 去掉临时容器销毁逻辑，改为清理 guide。
- `Live2DPositionEditor.createToolbar()`
  - 内联样式改为 class，方便响应式适配。
- `Live2DPositionEditor.updateDisplay()`
  - 确保显示值与真实舞台基准一致。

`初始模板/脚本/galgame通用生成器/数据库界面插件.css`
- 新增位置编辑工具栏样式类（含移动端媒体查询）。
- 新增位置编辑 guide 样式（非裁切层）。

---

## 4. 实施顺序（建议）

1. 先做“清场 + 主界面恢复”流程（风险低，立即改善交互）。
2. 再替换“临时容器编辑”为“真实舞台编辑”（核心改造）。
3. 最后做工具栏响应式重构与移动端收尾。
4. 完成后统一做手测与回归。

---

## 5. 验收标准

### 5.1 开始调整位置行为
- 点击后，所有其它窗口关闭，仅保留主界面与调整工具栏。
- 不会出现多个弹窗叠层或隐藏面板挡住主画面。

### 5.2 显示与结果一致
- 调整过程中角色不再被“临时容器”截断。
- 保存后回到正常播放，大小与位置与编辑时一致（误差可忽略）。
- 单角色/双角色场景都一致。

### 5.3 移动端可用性
- 在常见手机竖屏下，工具栏首屏可见且可滚动操作。
- “保存/取消/重置”始终可点击，不被底部 UI 挡住。

---

## 6. 风险与回滚

主要风险：
- 真实舞台编辑会影响现有 `Live2DStage` 挂载状态切换（与预览模式冲突）。
- 清场选择器若过宽，可能误关不该关的面板。

控制措施：
- 清场采用白名单/黑名单组合，先小范围选择器。
- 给编辑模式加状态锁，退出时保证恢复到进入前 mount 状态。

回滚策略：
- 保留旧版“临时容器编辑”分支开关（仅开发期），异常时可快速切回旧逻辑。

---

## 7. 手测清单

1. 从角色管理页进入 Live2D 设置，点击“开始调整位置”。
2. 验证是否自动清场并回到主界面。
3. 调整 X/Y/缩放后保存，观察实时与最终一致性。
4. 在双角色同屏下重复操作，确认不串位。
5. 在移动端竖屏/横屏测试工具栏可见性与可操作性。
