# 角色卡内嵌资源与绑定配置方案（图包远程 / Live2D / TTS）

目标：把「图包远程导入配置」「人物- Live2D 绑定（含位置/缩放）」「人物- TTS 绑定信息」**随角色卡一起分发**，落地到 `初始模板/脚本/galgame通用生成器/数据库界面插件.js`。

约束与原则：
- **不让 AI 看到**：配置只给插件读取，不应进入提示词/上下文注入。
- **适配离线写卡**：卡作者用 VSCode 写卡时，应能维护一份独立的配置 JSON，然后“粘贴/打包进角色卡”。
- **角色卡自包含**：尽量不依赖额外世界书文件；允许只存“远程指针/元数据”，大资源仍放远程或 IndexedDB 缓存。
- **兼容现状**：当前脚本大量使用 `localStorage` 与 `IndexedDB`；需要迁移/回退策略避免老用户配置丢失。

---

## 1. 现状梳理（脚本当前存储点）

### 1.1 图包/资源
- 立绘、背景、图包列表：IndexedDB（`DB_NAME=GalgameUIPluginDB`，stores: `sprites/backgrounds/imagePacks`）
- 图包“当前选择/渲染范围”：`localStorage`
  - `GalgameStore.STORAGE_KEYS.CURRENT_PACK`
  - `GalgameStore.STORAGE_KEYS.RENDER_SCOPE`
- 已有“远程资源链接 JSON”能力：
  - 导出时可生成 `remote_assets.json`（需要 baseUrl）
  - 导入侧已有 `importAssetsFromJson(file, targetPackId)`

### 1.2 Live2D
- Live2D 模型实体：IndexedDB（store `live2dModels`）
- Live2D 绑定开关与变换参数：`localStorage`
  - `CHAR_USE_LIVE2D_KEY = ${SCRIPT_ID}_char_use_live2d`
  - `LIVE2D_CONFIG_KEY = ${SCRIPT_ID}_live2d_config`

### 1.3 TTS
- 人物-音色绑定：`localStorage`
  - `GalgameStore.STORAGE_KEYS.CHAR_TTS_VOICE`
- TTS 全局开关：`localStorage`
  - `GalgameStore.STORAGE_KEYS.TTS_ENABLED`

结论：现状“换机器/分享角色卡”会丢配置，因为关键映射都在本地浏览器存储。

## 2. 角色卡内嵌配置的候选方案

### 方案 D（推荐，最适合 VSCode 离线写卡）：写入角色卡 `data.extensions` 自定义字段
落点：角色卡 JSON 的 `data.extensions.galgame_ui_plugin`（自定义扩展字段）。

做法：
- 卡作者维护一份独立的 `galgame-ui-plugin.config.json`（见示例文件），构建/发布角色卡时把这段 JSON 嵌入到卡的 `data.extensions.galgame_ui_plugin`。
- 插件运行时优先从 `data.extensions.galgame_ui_plugin` 读取配置；若不存在再回退到 `localStorage/IndexedDB` 的旧逻辑。

优点：
- 真正“在角色卡里”，可随卡导出/分享。
- 不会进入 AI 上下文（不需要世界书注入/开场白承载）。
- 有清晰的命名空间（例如 `galgame_ui_plugin.*`）。

缺点：
- 需要在脚本里新增一层“从角色卡扩展字段读取并应用配置”的适配代码（一次性成本，收益大）。

### 方案 C（可选）：写入「角色卡变量」（tavern_helper 角色卡变量）
落点：角色卡的 tavern_helper 扩展变量（在部分卡格式中会表现为 `data.extensions.tavern_helper` 的 `["variables", {...}]` 槽位）。

做法：
- 卡作者把配置放进 tavern_helper 的 `variables`（或由脚本在运行时写入 `getVariables/replaceVariables` 的角色卡变量表）。

优点：
- 对“脚本侧读写变量”更一致，配置可以通过 `getVariables({type:'character'})` 直接拿到。

缺点：
- 卡格式存在多个流派（`TavernHelper_scripts` vs `tavern_helper` map），离线作者更容易写错结构；因此不作为首推。

### 方案 A：在角色卡附加/内置“世界书/角色书”存配置（绿灯条目）
做法（两种实现）：
- A1：使用「角色书/Character Book」条目承载（卡内，最接近“随卡走”）
- A2：使用外部世界书（需要分发 worldbook 文件，不满足“单卡自包含”）

存储方式：
- 建议存到条目的 `extra` 字段；退化方案是把 JSON 放进 `content` 并用标记包裹。

优点：
- 编辑入口对部分作者更直观（世界书 UI）。

缺点：
- 容易误触“注入到上下文”（一旦条目被激活/constant），会把配置暴露给 AI。
- 外部世界书方案会破坏“单卡自包含”。

### 方案 B：把 JSON 放在开场白的第二条/第二 swipe（`first_messages[1]`）里
做法：
- 约定第二条开场白为配置区块，例如以 `[[GALGAME_CONFIG]]...[[/GALGAME_CONFIG]]` 包裹 JSON。
- 插件启动时扫描 `first_messages`，解析并消费配置。

优点：
- 不依赖变量接口；仅靠能读到角色卡文本即可实现。

缺点（重要）：
- 配置会出现在“开场白可选项”里，用户可能误点导致把 JSON 发进聊天。
- 文本字段存在被模型看见/进入上下文的风险（取决于客户端如何注入首条消息）。
- 可维护性差：后续要扩 schema、压缩、转义、分片等。

结论：
- **主路径选 D**（`data.extensions` 自定义字段，对离线写卡最友好且不会注入上下文）。
- C 作为“变量体系一致”的可选方案。
- A/B 只作为“兼容/兜底读取”，不要作为主存储。

## 3. 推荐的配置 Schema（v1 草案）

命名空间建议：`galgame_ui_plugin`.

### 3.1 嵌入结构（示例）
推荐写入角色卡：`data.extensions.galgame_ui_plugin = { ... }`。

示例（`galgame-ui-plugin.config.example.json` 的内容嵌入到卡里）：
```json
{
  "schema": "galgame_ui_plugin_config_v1",
  "assets": {
    "activePackId": "pack_xxx",
    "packs": [
      {
        "packId": "pack_xxx",
        "name": "图包名",
        "remoteAssetsUrl": "https://cdn.jsdelivr.net/gh/user/repo@main/remote_assets.json",
        "remoteBaseUrl": "https://cdn.jsdelivr.net/gh/user/repo@main/"
      }
    ]
  },
  "live2d": {
    "enabledMap": {
      "角色名": true
    },
    "models": {
      "角色名": {
        "source": "remote",
        "modelUrl": "https://example.com/model3.json",
        "transform": {
          "slot": "left",
          "scaleBase": "height",
          "scale": 1,
          "offsetX": 0,
          "offsetY": 0
        }
      }
    }
  },
  "tts": {
    "enabled": true,
    "characterVoice": {
      "角色名": "音色名"
    }
  }
}
```

说明：
- `remoteAssetsUrl` 建议优先使用：让“图包远程配置”只需 1 条 URL，不要把每张图的 URL 都塞进角色卡。
- `remoteBaseUrl` 可选：用于兼容旧导出逻辑或在缺少 `remoteAssetsUrl` 时拼接。
- Live2D 的 `transform` 字段应与脚本内部 `getLive2DConfig/setLive2DConfig` 的结构保持一致（避免二次映射）。

## 4. 导入与运行时流程（按主路径 D 设计）

### 4.1 启动时读取顺序
1. 从「角色卡扩展字段」读取 `data.extensions.galgame_ui_plugin`（主路径）
2. 若不存在：从 `localStorage` 读取现有映射（兼容旧用户）
3. 若仍不存在：尝试兜底读取 C/A/B（tavern_helper variables / 世界书 / 开场白标记）

### 4.2 资源导入策略（图包）
- 若配置包含 `remoteAssetsUrl`：
  - 插件 fetch JSON，复用现有 `saveSprite/saveBackground` 的 “imageUrl=远程URL” 方式写入 IndexedDB（或只写远程 url，不落 blob）
  - 允许“只导入链接，不下载 blob”（首次展示时再按需下载）
- 若只提供 `remoteBaseUrl`：
  - 走现有 `AssetIO.exportAllAssets(baseUrl)` 的同构格式（要求作者提供/确认 baseUrl）

### 4.3 Live2D 导入策略
- 卡内仅存远程 `modelUrl` + `transform`（以及启用开关）。
- 实体模型缓存仍放 IndexedDB（按需加载；失败可回退 CORS 代理策略）。

### 4.4 TTS 绑定策略
- 将 `getCharacterTTSVoice/setCharacterTTSVoice` 的存储层改为“优先角色卡变量”，`localStorage` 仅做回退。

## 5. “导出设置内容”怎么做（离线写卡工作流）

结论：**卡作者用 VSCode 写卡时，最省事的是维护一份独立 JSON 文件，然后构建/发布时嵌入角色卡**；导出入口不必放在插件内。

推荐交付物（给卡作者/仓库）：
- `galgame-ui-plugin.config.json`：配置文件（远程图包指针 + Live2D 绑定 + TTS 绑定）
- （可选）`galgame-ui-plugin.config.schema.json`：JSON Schema，VSCode 可做校验与补全
- 一段“如何嵌入角色卡”的说明（见下）

### 5.1 通用：把配置嵌入任何角色卡 JSON/PNG（不依赖打包工具）
目标是把配置写入角色卡的 `data.extensions.galgame_ui_plugin`。

本仓库提供了一个独立 CLI（不依赖 `nova-creator-cli`）：
- 注入：`node scripts/galgame-ui-plugin-config.js inject <card.json|card.png> <config.json> --out <out.json|out.png>`
- 提取：`node scripts/galgame-ui-plugin-config.js extract <card.json|card.png> --out <config.json>`
- 移除：`node scripts/galgame-ui-plugin-config.js remove <card.json|card.png> --out <out.json|out.png>`

你也可以不用脚本，直接在 VSCode 里把 JSON 对象手动粘贴到 `data.extensions.galgame_ui_plugin`。

### 5.2 从酒馆面板一键导出配置 JSON（推荐）
如果你是先在酒馆里用面板调好了 Live2D 位置/缩放、TTS 绑定等，然后想导出为 `galgame-ui-plugin.config.json` 给 VSCode 写卡用：
- 打开插件「资源管理器」
- 点击右上角 `导出` 下拉菜单
- 选择 `导出角色卡配置JSON`
- 按提示可选填写 `remote_assets.json` 完整 URL 或 baseUrl（留空也可）
- 将会下载 `galgame-ui-plugin.config.YYYY-MM-DD.json`（并尝试复制到剪贴板）

兼容/兜底：如果你使用的是旧版本脚本，资源管理器里没有该导出项：
- 打开 SillyTavern 页面，按 F12
- 把 `初始模板/脚本/galgame通用生成器/tools/export-galgame-ui-plugin-config.js` 全文件复制到 Console 执行
- 运行：`GalgameUiPluginConfigExporter.runInteractive()`

### 5.3 （可选）nova-creator-cli 工作流
如果你用本仓库自带的离线打包工具（`初始模板/脚本/nova-creator-cli/build-card.js`）：
- 在 YAML 配置里加一行 `galgame_ui_plugin: <你的json路径>`，打包时会自动写入 `data.extensions.galgame_ui_plugin`
- `unpack-card.js` 解包时也会把 `data.extensions.galgame_ui_plugin` 还原成 `galgame-ui-plugin.config.json` 并写回 YAML

关于“导出时是不是要自己填远程地址？”：
- 是的，**只要你希望别人能从远程拉资源，就必须有一个稳定的远程地址**（GitHub/jsDelivr 只是其中一种）。
- 但可以把交互做得更省心：
  - 复用现有 `导出GitHub资源包` 的引导：输入 `user/repo + branch/tag` 自动生成 `baseUrl`
  - 最终在卡内建议存 `remoteAssetsUrl`（而不是要求用户手填每个资源链接）

独立 HTML 页面适用场景（可选）：
- 你希望“没装插件的人”也能离线编辑配置并生成 JSON
- 你想做批量生产（例如从表格批量生成配置片段）
- 本仓库已提供离线工具：`初始模板/脚本/galgame通用生成器/tools/galgame-ui-plugin-config-tool.html`（注入/提取/移除 `data.extensions.galgame_ui_plugin`）
  - 支持 `SillyTavern` 导出的 `.json` 角色卡与 `.png` 角色卡

## 6. 迁移与验收

### 6.1 迁移策略（不破坏老用户）
- 若卡内无配置但 `localStorage` 有：提供一次性按钮 `迁移到角色卡`（写入变量后可选择保留或清理 localStorage）。

### 6.2 验收标准（最小闭环）
- 导出一个角色卡到新环境导入后：
  - 能自动识别并切换到配置指定的远程图包（至少背景/立绘能按远程链接显示）
  - 指定角色出现时 Live2D 能按配置的位置/缩放显示
  - 角色说话时 TTS 自动使用绑定音色（无需再次手动设置）
