# 角色卡直存与前端包嵌入实施计划（不走世界书）

## 1. 目标

- 把插件关键配置从世界书/本地存储迁移为**角色卡直存**。
- 实现“资源设置绑定到角色卡”的**一键导入/一键导出**闭环。
- 参考 `higanbana` 思路，规划“前端项目 zip 嵌入角色卡”的扩展能力（分阶段落地）。

---

## 2. 约束与原则

- 配置必须对 AI 不可见，不进入提示词和上下文注入链路。
- `数据库界面插件.dist.js` 只做构建产物，不直接改。
- 保持对老用户兼容：已有 `localStorage + IndexedDB` 数据可迁移、可回退。
- 优先做稳定 MVP，再做大体积前端包嵌入。

---

## 3. 存储策略（主方案）

### 3.1 主存储落点

- 使用角色卡字段：`data.extensions.galgame_ui_plugin`
- 读取优先级：
  1. `data.extensions.galgame_ui_plugin`
  2. 旧本地存储（`localStorage/IndexedDB`）
  3. 兼容兜底（可选：角色卡变量）

### 3.2 配置 Schema（v2 草案）

```json
{
  "schema": "galgame_ui_plugin_config_v2",
  "meta": {
    "updatedAt": "2026-02-14T00:00:00.000Z",
    "source": "galgame-ui-plugin"
  },
  "assets": {
    "activePackId": "pack_main",
    "packs": [
      {
        "packId": "pack_main",
        "name": "主图包",
        "remoteAssetsUrl": "https://.../remote_assets.json",
        "remoteBaseUrl": "https://.../"
      }
    ]
  },
  "live2d": {
    "enabledMap": {},
    "models": {}
  },
  "tts": {
    "enabled": true,
    "characterVoice": {}
  },
  "webBundles": []
}
```

说明：
- `webBundles` 先预留，MVP 阶段可为空。
- 大资源仍建议远程托管，角色卡内优先存“指针 + 绑定关系”。

## 4. 功能闭环设计

### 4.1 导出

- 在资源管理 `导出` 菜单新增：
  - `导出角色卡配置JSON`
  - `写入当前角色卡（覆盖/合并）`
- 导出内容含：图包远程配置、Live2D 绑定、TTS 绑定。

### 4.2 导入

- 在资源管理 `导入` 菜单新增：
  - `从当前角色卡一键导入`
  - `从角色卡配置JSON导入`
- 导入过程：
  1. 校验 schema
  2. 应用图包配置（remote_assets）
  3. 应用 Live2D 配置
  4. 应用 TTS 绑定

### 4.3 自动应用

- 插件初始化与切卡事件触发时自动检查当前角色卡配置并应用。

### 4.4 迁移

- 提供 `迁移当前本地设置到角色卡` 一次性按钮：
  - 迁移后可选“保留本地副本”或“清理本地副本”。

---

## 5. 与 higanbana 的结合（扩展阶段）

参考能力：
- 前端项目 zip 嵌入角色卡
- 楼层内 HTML 渲染
- 占位符复用嵌入项目

本项目落地策略：
1. **阶段 1（MVP）**：先做配置直存，不嵌入大 zip。
2. **阶段 2（扩展）**：增加 `webBundles` 支持，允许把前端 zip 作为 base64 分片写入角色卡。
3. **阶段 3（兼容）**：研究对 `higanbana` 既有字段/占位符协议的兼容读取（如字段命名与 payload 包装格式）。

## 6. 代码改动分层计划

### A. 新增角色卡配置读写层

- 新增模块（建议）：`src/core/card-config.js`
- 能力：
  - `readCurrentCardConfig()`
  - `writeCurrentCardConfig(config, { merge })`
  - `validateCardConfig(config)`
  - `migrateLocalToCardConfig()`

### B. 接入导入导出入口

- `src/ui/asset-manager-modal.js`
  - 导出菜单新增“角色卡配置”项
  - 导入菜单新增“一键从角色卡导入”
- `src/ui/asset-io.js`
  - 增加 `exportCardConfig()` / `importFromCardConfig()` / `applyCardConfig()`

### C. 接入运行时应用

- `src/init.js`
  - 初始化后自动应用角色卡配置
  - `CHAT_CHANGED` 后重新应用

### D. 绑定存储层重定向

- `src/audio/tts-config.js`
  - 角色音色映射优先读写角色卡配置，`localStorage` 回退
- `src/live2d/render-mode.js`
  - `enabled/config` 优先读写角色卡配置，`localStorage` 回退

## 7. 里程碑

### M1（先交付）
- 角色卡配置 JSON 导出
- 从当前角色卡一键导入
- 初始化/切卡自动应用

### M2
- 本地数据迁移到角色卡
- UI 上增加迁移状态与冲突提示

### M3（扩展）
- `webBundles` zip 嵌入能力（分片、压缩、大小警戒）
- 占位符复用和楼层 HTML 渲染联动

---

## 8. 风险与控制

- 角色卡体积膨胀：
  - 控制 `webBundles` 单包大小；超阈值提示改用远程。
- 格式兼容差异（JSON/PNG 卡）：
  - 统一走现有 `scripts/galgame-ui-plugin-config.js` 的读写链路。
- 安全风险（HTML 渲染）：
  - 默认白名单标签/属性，禁止危险脚本执行。

---

## 9. 验收标准

- 不依赖世界书，角色卡可独立携带并恢复资源绑定配置。
- 新环境导入角色卡后：
  - 图包资源可恢复（远程地址 + 映射关系）。
  - Live2D 绑定可恢复（远程地址 + 映射关系）
  - TTS 角色音色绑定可恢复
- 老用户数据可一键迁移且不丢失。
- `dist` 构建产物不手改，源码改动可正常构建发布。
