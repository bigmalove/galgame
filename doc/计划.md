# GPT-SoVITS v2ProPlus（api_v2.py）音色/模型接入升级计划

## 0. 先回答：音色列表（JSON）是什么？
当前脚本里「音色列表（JSON）」本质是一个**音色 Profile 配置表**：用一个 `name`（音色名）去绑定 GPT-SoVITS 推理需要的参数（参考音频、提示文本、语言、以及可选的 GPT/SoVITS 权重路径）。

原因：GPT-SoVITS 的 `/tts` 并不会像 LittleWhiteBox 那样天然提供“可选音色 ID 列表”，它需要你提供 `ref_audio_path / prompt_text / prompt_lang / text_lang` 等参数；如果还要“一键切模型”，还需要调用 `/set_gpt_weights` 与 `/set_sovits_weights`。

因此必须有一份「音色名 → 推理参数」的映射表；脚本才能做到：
- COT/解析仍然只写 `tts="speaker=音色名;..."`（不用改 COT）
- 播放时根据音色名自动找对应的模型 + 参考音频 + prompt

## 0.1 现状痛点（你反馈的点）与根因

### A) “导入路径前缀”不直观
你看到的「导入路径前缀」其实是在解决一个现实限制：

- GPT-SoVITS 的 `/tts` 需要的 `ref_audio_path`、`weights_path` 是**服务端文件系统路径**（相对 `api_v2.py` 启动工作目录，或绝对路径）。
- 但酒馆前端在**浏览器安全限制**下，通常拿不到你本机的“绝对路径”（只能拿到文件名/相对路径，比如 `奥泽美咲/xxx.mp3`）。

所以必须有一个“映射/补全”机制：
- **最理想**：能拿到绝对路径 → 导入时就自动填完整路径（仅在 ST 桌面版/Electron 的 `File.path` 可用时可做到）
- **浏览器环境**：拿不到绝对路径 → 就只能导入“相对路径”，再让用户告诉我们“这些文件在 GPT-SoVITS 服务端的哪个目录下”（这就是“前缀/根目录”的意义）

建议把 UI 文案从“导入路径前缀”改成更准确的：
> **服务端路径前缀（GPT-SoVITS 工作目录下）**

并在 UI 里给出例子：
- 你导入得到 `奥泽美咲/xxx.mp3`，但实际文件在 `output/奥泽美咲/xxx.mp3` → 前缀填 `output/`

### B) “导入文件夹像上传文件”
前端“导入文件夹”用的是浏览器的文件选择器（`webkitdirectory`）。
- **不会把文件上传到 GPT-SoVITS**（除非我们主动读取并 POST 上传）
- 它只是用来拿到“文件名/相对路径/大小”等元信息，从而自动生成 voice profile

如果你期望的是“输入一个本机路径字符串 → 自动扫描目录”，那就必须引入**后端扫描**（见阶段 D2），纯前端做不到。

### C) “导入 JSON 点播放没有触发 / API 毫无反应”
你给的列表里第一条音色 `新音色` 的 `refAudioPath=""`，如果“试听/默认音色”恰好选中了这条：
- 脚本会在前端直接判定“缺少 refAudioPath”，**不会调用 API**（看起来就像“API 没反应”）

计划里需要补：
- 试听默认选择“第一个 refAudioPath 非空的音色”
- 保存/导入时对每条音色做校验（缺 refAudioPath 的标红/禁用试听）

## 0.2 你现在就能怎么用（最小可用流程 / 先跑起来）
> 用来回答你问的“导入路径前缀是什么？为什么不能自动填完整路径？”以及“为什么我点播放没触发”。

1) **先确认：GPT-SoVITS 服务端能访问到这些文件**
   - `refAudioPath/gptWeightsPath/sovitsWeightsPath` 的路径语义是：**GPT-SoVITS（api_v2.py）运行环境里的文件路径**。
   - 最稳的做法：把模型包文件夹放到 GPT-SoVITS 运行目录下面（例如 `runtime/voices/奥泽美咲/...`），然后用相对路径。

2) **“服务端路径前缀/根目录”怎么填**
   - 如果你导入出来是：`奥泽美咲/xxx.mp3`（浏览器只能给相对路径）
   - 但你实际把文件放在：`runtime/voices/奥泽美咲/xxx.mp3`
   - 那么前缀就填：`voices/`（最终给 API 的路径就是 `voices/奥泽美咲/xxx.mp3`）
   - 你也可以把前缀写成绝对路径（服务端可用的那种），但不同机器/目录会更难迁移。

3) **先别把“空模板音色”当默认音色**
   - 像你示例 JSON 里 `新音色` 的 `refAudioPath=""`，用于占位可以，但它**必然无法试听**。
   - 先把默认音色/试听音色切到 `奥泽美咲`（有 refAudioPath 的那条），否则前端会直接拦截，看起来像“API 不响应”。

4) **如果还是无声**
   - 检查 `apiUrl` 是否能在酒馆页面打开（同机 `http://127.0.0.1:9880` 通常可行）
   - 检查 `useCorsProxy`（跨域/混合内容问题时建议开）
   - 用 GPT-SoVITS 的 WebUI/命令行先验证：这些 `ref_audio_path/weights_path` 在服务端确实存在

## 2. 数据结构（建议最终落地 schema）
> 目标：既能手动编辑，也方便后续“扫描导入/导入文件”。

### 2.1 全局配置：`settings.gptSoVits`
```json
{
  "apiUrl": "http://127.0.0.1:9880",
  "endpoint": "/tts",
  "useCorsProxy": true,
  "mediaType": "wav",
  "streamingMode": true,
  "textLang": "auto",
  "textSplitMethod": "cut5",
  "speedFactor": 1,
  "voices": []
}
```

### 2.2 音色 Profile：`settings.gptSoVits.voices[]`
```json
{
  "name": "景元",
  "desc": "v2ProPlus-景元",

  "gptWeightsPath": "GPT_weights_v2ProPlus/景元/xxx.ckpt",
  "sovitsWeightsPath": "SoVITS_weights_v2ProPlus/景元/yyy.pth",

  "refAudioPath": "runtime/ref_audio/景元/ref.wav",
  "promptText": "我是……（参考音频对应文本）",
  "promptLang": "zh",
  "textLang": "zh"
}
```

字段说明（最小可用）：
- 必填：`name`、`refAudioPath`
- 推荐：`promptText`、`promptLang`、`textLang`
- 进阶：`gptWeightsPath`、`sovitsWeightsPath`（用于自动切模型）

## 3. 功能实现计划（分阶段）

### 阶段 A（待做，最优先）：把“JSON 文本框”升级为真正的音色管理器
**目标**：不用写 JSON；并把“路径/导入/校验/试听”做成可理解、可验证的流程。

- UI：新增「GPT-SoVITS 音色管理」弹窗（表格/卡片）
  - 列：音色名、GPT权重、SoVITS权重、参考音频、promptText、promptLang、textLang
  - 操作：新增、编辑、删除、复制、导入、导出、试听、校验
- 导入：
  - 从文件导入（`<input type="file" accept=".json">`）
  - 从剪贴板粘贴 JSON（兼容你现有的 JSON 格式）
  - 从文件夹导入（识别 `ckpt/pth/audio` 并生成条目；不会上传文件内容）
- 导出：
  - 导出到剪贴板
  - 下载为 `.json`（浏览器下载）
- 关键 UX（解决你遇到的困惑）：
  - UI 文案改名：
    - “导入路径前缀”→ **服务端路径前缀/根目录（GPT-SoVITS 可访问）**
    - “导入文件夹”→ **选择文件夹（仅读取目录结构，不上传文件）**
  - 把“路径问题”说清楚：`refAudioPath/gptWeightsPath/sovitsWeightsPath` 必须是 **GPT-SoVITS 服务端可访问的路径**
  - 支持 2 种路径模式：
    1) **绝对路径模式**（仅桌面版可用时自动填充）
    2) **服务端根目录 + 相对路径**（浏览器环境）：引导用户设置“服务端路径前缀/根目录”
  - 导入后先显示“预览与校验结果”：缺 refAudioPath 的条目提示“不会触发 API”
  - 试听强制要求“选择一个音色”，并默认选中“第一个可用音色（refAudioPath 非空）”
  - 失败时显示 **GPT-SoVITS 返回的 JSON 错误**（例如找不到文件/权重）而不是只显示“播放失败”

验收：
- 不接触代码也能完成新增音色并试听
- 用户能看懂“为什么需要路径”，并能在 UI 内完成校验

### 阶段 B（已完成基础版，需补完善）：每个音色自动切换 GPT/SoVITS 权重
**目标**：同一套解析（speaker=音色名），播放时能自动用对应模型。

实现：
- 在播放 GPT-SoVITS 前：
  - 若音色配置了 `gptWeightsPath`：调用 `GET {apiUrl}/set_gpt_weights?weights_path=...`
  - 若音色配置了 `sovitsWeightsPath`：调用 `GET {apiUrl}/set_sovits_weights?weights_path=...`
- 做缓存：
  - 记录 `currentGptWeightsPath/currentSovitsWeightsPath`
  - 相同则跳过切换（避免每句都切）
- 失败策略：
  - 切换失败：提示错误 + 不继续播放（或降级继续播放，但要有开关）

验收：
- 多个角色/音色轮流说话时，权重会自动切换且不会频繁重复请求

### 阶段 C：参考音频与 prompt 体验优化
**目标**：参考音频路径更好填、prompt 更不容易错。

实现建议：
- 为 `refAudioPath` 提供“最近使用/收藏”列表
- 试听按钮支持：
  - 选择任意音色一键试听
  - 支持短文本（默认）
  - 失败提示包含：API地址/代理/权重路径/参考音频路径

验收：
- 新增音色配置后，能快速通过试听验证可用

### 阶段 D（部分已完成）：快捷导入（按“你要的是路径”优先级排序）
> 这是你想要的“一键加载目录里所有模型/参考音频”的关键，但需要取舍。

**方案 D2（推荐，最符合“输入路径→扫描”的直觉）**：SillyTavern 后端扫描指定目录
- 在 ST 后端（Node）增加一个安全的扫描 endpoint（白名单/仅允许扫描 GPT-SoVITS 根目录下）
- 前端只需要：输入一个目录路径（例如 `D:\\工具软件\\GPT-SoVITS-v2pro-20250604\\output\\奥泽美咲`）→ 点击“扫描导入”
- 后端返回：每个模型包的绝对路径（ckpt/pth/ref audio）+ 推断的 promptText/lang

优点：
- 终于可以“自动填完整路径”，不需要前缀
- 用户体验最符合预期（你说的“需要的是文件路径和文件名”）

缺点：
- 需要做后端（权限/安全要严格）

**方案 D1（不改 GPT-SoVITS，不写后端，最稳）**：本机脚本扫描生成 voices.json
- 新增一个 `scripts/scan_gpt_sovits.ps1`：
  - 输入：GPT-SoVITS 根目录（例如 `D:\\工具软件\\GPT-SoVITS-v2pro-20250604`）
  - 扫描：`GPT_weights*`、`SoVITS_weights*`、以及你指定的 ref_audio 目录
  - 输出：`voices.json`（符合上面 schema）
- UI：增加「导入-从扫描文件」按钮

优点：实现快、稳定、安全  
缺点：需要跑一次脚本

**方案 D0（纯前端兜底，已完成基础版）**：选择文件夹导入（适配“模型包放同一文件夹”）
- 说明：它不会上传文件内容，只拿文件名/相对路径做推断（浏览器做不到“输入路径→扫描”）
- 支持两种导入粒度（规划）：
  - 选择一个“音色包文件夹”（包含 `*.ckpt/*.pth/若干参考音频`）→ 生成 1 条音色
  - 选择一个“总目录”（里面包含多个子文件夹，每个子文件夹是一个音色包）→ 批量生成多条音色
- 识别规则（建议/默认）：
  - `*.pth`：取**体积最大**的文件作为 SoVITS 权重
  - `*.ckpt`：优先取与 `*.pth` **同名**的 ckpt，否则取体积最大的 ckpt 作为 GPT 权重
  - 参考音频：优先 `wav`，否则 `flac/ogg/mp3`；同时会尝试从音频文件名抽取 `promptText`
  - `promptLang/textLang`：根据 `promptText` 自动判断（假名→`ja`，英文→`en`，默认→`zh`）
  - 忽略：`*.zip`、临时文件、明显无关文件
- 路径问题：浏览器拿不到绝对路径，所以需要设置 **服务端路径前缀/根目录**（例如 `voices/` 或 `output/`）来拼成 GPT-SoVITS 能找到的路径

（不推荐）改 GPT-SoVITS `api_v2.py` 增加 list 接口：维护成本高，升级麻烦。

验收：
- 能从你截图这种目录结构里批量生成音色条目

## 5. 风险与注意事项
- `/set_gpt_weights` 与 `/set_sovits_weights` 会改变 GPT-SoVITS 服务端的“全局状态”：
  - 同时开多个酒馆页面/多个客户端可能互相抢模型
  - 需要在前端做串行队列（一次只播一个）
- `refAudioPath` 是 GPT-SoVITS 服务端可访问的路径：
  - 不是酒馆里的 `/user/files/...` 路径
  - 建议统一放在 GPT-SoVITS 根目录某个固定目录下并用相对路径
- 口型同步依赖同源/代理：
  - 建议默认开启 `useCorsProxy`
