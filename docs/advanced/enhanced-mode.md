# 加强模式

## 什么是加强模式

加强模式（Enhanced Mode）是为了解决 **AI 不能稳定输出 Galgame 格式** 的问题而设计的。

正常情况下，AI 需要同时完成两件事：
1. 创作故事内容
2. 按 Galgame 标签格式输出

部分模型在这两件事之间顾此失彼。加强模式将它们拆分为 **两次生成**：

| 步骤 | 任务 |
|---|---|
| **第一次生成** | AI 专注于创作故事内容（可以不遵循格式） |
| **第二次生成** | 插件自动将故事内容发给 AI，要求格式化为 Galgame 标签 |

## 启用加强模式

1. 打开 **设置面板**
2. 找到「加强模式」区域
3. 开启后，配置第二次生成使用的 LLM

## 配置项

### 第二次生成使用的 LLM

| 选项 | 说明 |
|---|---|
| **跟随酒馆当前 API 与预设** | 使用酒馆当前的连接与预设（保留预设里的破限等提示词），不发送聊天记录 |
| **使用酒馆连接配置** | 选择一个酒馆「连接配置」（Connection Profile）独立发请求，**不会切换酒馆当前的连接、模型和预设** |

**发送世界书内容**（两种来源通用，默认关闭）：开启后第二次生成会附带按原文激活的世界书条目，帮助模型识别角色、地点等名称，代价是更多 token。只附带「角色定义之前 / 之后」位置的条目，按深度插入的条目始终不发送。

- 跟随酒馆当前 API：由酒馆按当前预设注入；关闭时清空这两个位置的世界书
- 使用酒馆连接配置：插件按原文扫描当前激活的世界书（不触发激活事件、不影响粘性 / 冷却计时），作为参考资料附在请求最前面

选择「使用酒馆连接配置」后：

| 配置 | 说明 |
|---|---|
| **连接配置** | 酒馆「API 连接」页面里用连接配置管理保存的配置；点右侧按钮可刷新列表 |
| **模型** | 默认跟随连接配置自带的模型；点右侧按钮从该配置对应的 API 拉取模型列表后选择，拉取失败时可选「手动输入模型名」 |
| **最大回复长度** | 0 表示跟随连接配置绑定的预设；格式化输出约等于原文长度加标签，正文较长时请调大 |
| **测试连接** | 用当前配置发一条极短的请求，确认密钥、模型可用 |

请求使用连接配置绑定的密钥与预设参数（温度、最大长度等），只发送格式化指令和原文（以及开启时的世界书内容），不包含角色卡和聊天记录。

::: tip 推荐
第二次生成可以使用较便宜/较快的模型，因为它只需要做格式化，不需要创作能力。
:::

::: warning
旧版的「连接配置 / 模型 / 预设」勾选项通过临时切换酒馆全局设置实现，已移除；旧设置中勾选的连接配置和模型会自动迁移为「使用酒馆连接配置」。旧版的世界书三选一改为「发送世界书内容」开关：原先选「不使用任何世界书」的迁移为关闭，其余迁移为开启；「指定世界书列表」不再支持。
:::

### 查看提示词

点击「查看提示词」按钮可以查看加强模式最近一次生成使用的完整提示词，包括：

- **使用的 LLM**：酒馆当前 API，或「连接配置 / 模型」
- **世界书**：是否发送；使用连接配置时还会显示附带的世界书内容（World Info）
- **System Prompt**：系统提示词
- **First Result**：第一次生成的原始结果
- **User Prompt**：发给第二次生成的用户提示词

这对调试格式化效果非常有用。

## 格式化结果存放在哪里

格式化后的文本 **不会写入酒馆正文，也不会新增 swipe**，而是保存在该楼层的附加数据（`extra`）里，只在 Galgame 界面中显示：

- 关闭 Galgame 界面后，酒馆聊天里仍是第一次生成的原文
- 每个 swipe 各自保存自己的格式化结果，左右切换回复互不影响
- 编辑或续写已格式化的回复后，旧的格式化结果自动失效，并按新正文重新格式化
- 旧版本保存为 swipe 的格式化版本仍可正常显示

## 使用流程

1. 开启加强模式
2. 正常发送消息
3. AI 先完成第一次生成（内容创作），正文照常写入酒馆
4. 插件自动触发第二次生成（格式化），Galgame 界面流式显示格式化进度
5. 完成后格式化结果保存到楼层附加数据，Galgame 界面以 Galgame 格式展示
6. 多条回复先后完成时，第二次生成会排队依次执行
